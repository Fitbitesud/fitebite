# لوحة تحكم فيتبايت — Sanity Studio

هذه لوحة التحكم التي يدار منها الموقع: الأصناف، التصنيفات، وتعليقات الزوار (موافقة/نشر).

## خطوات الربط أول مرة

1. أنشئ حساباً ومشروعاً مجانياً على https://www.sanity.io (اختر Free plan).
2. من https://www.sanity.io/manage انسخ **Project ID**.
3. في مجلد `studio/` انسخ `.env.example` إلى `.env.local` وضع المعرّف:
   ```
   SANITY_STUDIO_PROJECT_ID=ضع_المعرّف_هنا
   SANITY_STUDIO_DATASET=production
   ```
4. ثبّت وشغّل اللوحة محلياً:
   ```
   cd studio
   npm install
   npm run dev        # تفتح على http://localhost:3333
   ```
   سجّل الدخول بحساب Sanity نفسه، وأنشئ الداتاسيت باسم `production` عند أول تشغيل.
5. انشر اللوحة مستضافةً مجاناً على Sanity:
   ```
   npm run deploy     # تصبح على https://<project-id>.sanity.studio
   ```

## إدخال البيانات

- **شعار الشريط العلوي**: في «إعدادات الموقع → الهوية والشعار» حقلان:
  «شعار الشريط العلوي (خلفية فاتحة)» للشريط فوق الخلفية الفاتحة (صفحتا القائمة والباقات، وبعد التمرير)،
  و«شعار الشريط العلوي (خلفية داكنة) — اختياري» للشريط أعلى الصفحة الرئيسية وللتذييل.
  الصيغ المقبولة PNG/SVG/WebP/JPG (الأفضل بخلفية شفافة)، وبلا صورة للخلفية الداكنة يُستخدم الشعار الأساسي في كل المواضع.
- **مناطق التوصيل وأسعارها**: في «إعدادات الموقع → مناطق التوصيل وأسعارها» أضف لكل منطقة
  «اسم المنطقة» و«سعر التوصيل الثابت». السعر يُضاف **مرة واحدة** إلى إجمالي الطلب عندما يختار
  العميل تلك المنطقة في السلة، ويظهر في زر إتمام الطلب وفي رسالة واتساب. اكتب `0` (أو اتركه فارغاً)
  لتوصيل بدون رسوم — وهذا هو الافتراضي لكل المناطق حتى تحدّد الأسعار.
  المناطق القديمة المحفوظة كنص فقط تبقى تعمل بسعر 0؛ حوّل أي واحدة منها إلى «منطقة توصيل» لتكتب سعرها.
- **نص التوصيل الاحتياطي**: في «إعدادات الموقع → الأرقام والتواصل» حقل «نص التوصيل الاحتياطي
  (قبل اختيار المنطقة)». يظهر فقط عندما يطلب العميل توصيلاً قبل اختيار المنطقة، وبعد الاختيار
  يحل محلّه سعر التوصيل الثابت للمنطقة (الفارغ يبقي: مع مندوب التوصيل).
- **أصناف القائمة**: اذهب لقسم «أصناف القائمة» وأضف الأصناف (الاسم، التصنيف، السعر، الصورة، الماكروز…).
  يمكنك استيراد الأصناف الحالية دفعة واحدة لاحقاً عبر سكربت `sanity dataset import`.
- **تعليقات الزوار**: عند تفعيل توكن الكتابة وإعداد CORS، يصل التعليق إلى Sanity كمسودة غير منشورة، بحالة `approved: false`. راجع المسودة ثم فعّل «موافَق عليه» وانشرها ليظهر التعليق للزوار. إذا لم يُضبط التوكن أو فشل الإرسال، يُحفظ التعليق على جهاز صاحبه فقط ويجب إرساله عبر واتساب.

## سكربتات الصيانة

- **`scripts/fix-spelling.ts`** — يصحح الأخطاء الإملائية الشائعة في نصوص الإعدادات (أهمها همزة
  «الأحمر»: «الاحمر» ← «الأحمر»، مثل عنوان «بورتسودان البحر الاحمر») داخل الداتاسيت مباشرة:
  ```sh
  cd studio
  npx sanity exec scripts/fix-spelling.ts --with-user-token
  ```
  يحتاج تسجيل الدخول مسبقاً (`npx sanity login`)، ويعدّل الوثائق المنشورة والمسودات.
  الموقع يصحح نفس الأخطاء لحظة العرض أيضاً (حارس مؤقت في `lib/site-data.ts`)، لكن تشغيل
  السكربت يجعل لوحة التحكم نفسها تعرض الكتابة الصحيحة من المصدر.

## ربط الموقع باللوحة

محلياً، ضع متغيرات البيئة الآتية في جذر المستودع داخل `.env.local`:

```
NEXT_PUBLIC_SANITY_PROJECT_ID=<نفس المعرّف>
NEXT_PUBLIC_SANITY_DATASET=production
NEXT_PUBLIC_SANITY_COMMENT_TOKEN=<توكن Sanity يسمح بإنشاء المستندات في هذا الداتاسيت>
```

للنشر، أضفها في GitHub → **Settings → Environments → github-pages → Secrets** (أو في أسرار
المستودع) بالأسماء التي يقرأها الـ workflow، من دون بادئة `NEXT_PUBLIC_`:

```
SANITY_PROJECT_ID=<نفس المعرّف>
SANITY_DATASET=production
SANITY_API_VERSION=2025-02-19
SANITY_COMMENT_TOKEN=<توكن التعليقات الاختياري>
```

مهمة البناء تعمل ضمن بيئة `github-pages`، لذلك تصلها أسرار البيئة وأسرار المستودع معاً.

**مهم:** `comment` هو نوع مستند في مخطط Sanity، وليس اسم صلاحية للتوكن؛ لن تجد بالضرورة خياراً باسم `comment` في صفحة التوكنات. الموقع ينفذ `client.create()` مع معرّف يبدأ بـ`drafts.` لإنشاء مسودة `_type: "comment"` في الداتاسيت المحدد، بدلاً من إنشاء مستند منشور مباشرةً. هذا يناسب دور Contributor إذا كان يسمح بإنشاء المسودات. راجع المسودة في Studio، وفعّل الموافقة ثم انشرها كي تظهر للزوار. لا تختَر Administrator كحل سريع.

أضف في Sanity → API → CORS Origins كلاً من `https://fitbite-sudan.com` و`https://www.fitbite-sudan.com` و`https://fitbitesud.github.io` و`http://localhost:3000`، وفعّل **Allow credentials** للموقع. (بدون إضافة الدومين الجديد هنا سيفشل جلب بيانات لوحة التحكم الحية من متصفح الزائر على الدومين الجديد ويعود الموقع للبيانات المحلية.) وبعد إضافة أو تغيير GitHub Actions secret باسم `SANITY_COMMENT_TOKEN`، أعد تشغيل **Deploy to GitHub Pages**؛ لأن `NEXT_PUBLIC_SANITY_COMMENT_TOKEN` يُضمّن في ملفات الموقع وقت البناء. يجب أن يطابق Project ID واسم الداتاسيت في النشر ما تستخدمه لوحة Studio. التعليق الناجح يصل إلى قائمة «تعليقات الزوار» بحالة `approved: false`؛ عدم الموافقة يمنع ظهوره للزوار، لكنه لا يفترض أن يخفيه من Studio.

**تنبيه أمني مهم:** لأن الاستضافة ثابتة على GitHub Pages والمتغير اسمه `NEXT_PUBLIC_SANITY_COMMENT_TOKEN`، فالتوكن يظهر في ملفات JavaScript للزوار. حتى توكن الإنشاء فقط يمكن إساءة استخدامه، كما لا يمنع عميل معدل من إرسال `approved: true`. للحماية الكاملة يلزم وسيط خادمي يحتفظ بالتوكن سراً. من دون التوكن أو عند فشل الإرسال يحفظ النموذج التعليق على جهاز الزائر ويعطيه رابط إرساله للإدارة عبر واتساب.

قراءة التعليقات المعتمدة من Sanity عامة ولا تحتاج إلى توكن؛ التوكن وCORS مطلوبان فقط لإرسال تعليقات الزوار إلى لوحة التحكم.
