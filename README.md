# فيتبايت 🌿 — موقع مطعم الطعام الصحي

موقع طلبات أونلاين لمطعم **فيتبايت** المتخصص في الطعام الصحي، مبني بهوية المطعم البصرية الرسمية
(أخضر زيتوني داكن + كريمي + شوكة نحاسية)، **بدون أي نص إنجليزي في الشعار** — الكلمة المرافقة
للعلامة عربية: «فيتبايت» مع سطر الهوية المترجم: «طعام صحي للضخامة والتنشيف».

## أبرز المميزات

- 🎬 **شاشة تحميل متحركة** مبنية على الشعار نفسه: القوس يُرسم، الدمبل يهبط «ويرفع»، الحرفان
  يُرسمان، الشوكة والورقة تقفزان، ثم الكلمة العربية وشريط تقدم، وستارة صاعدة تكشف الموقع
  (قابلة للتخطي بالنقر).
- 🛒 **سلة طلبات كاملة** (درج جانبي + حفظ في `localStorage` + عدّاد في الهيدر + توست إضافة).
- 📲 **تحويل السلة إلى رسالة واتساب مفصّلة** تُفتح على الرقم المسجّل في `lib/config.ts` وتشمل:
  رقم الطلب، التاريخ والوقت، بيانات العميل (اسم/جوال/منطقة/عنوان/ملاحظات/طريقة دفع)،
  كل صنف بكميته وسعره وسعراته، إجمالي السعرات والبروتين، المجموع الفرعي، التوصيل
  (مع مندوب التوصيل)، والإجمالي.
- 🥗 قائمة مصنّفة (باولز، سلطات، مشويات وبوكسات، فطور، مشروبات) مع **ماكروز لكل وجبة**
  (سعرات/بروتين/كارب/دهون) وشارات وسوم و«الأكثر طلباً».
-  أقسام الهوية: «ما يميز فيتبايت» الأربعة من البوستر الرسمي، شريط وعود متحرك،
  كيف تطلب، آراء العملاء، بانر CTA، وفوتر كامل.
- 📱 متجاوب بالكامل RTL بخط Cairo، وأنيميشن كشف عند التمرير (Framer Motion).

## التقنية

Next.js 15 (App Router) + TypeScript + Tailwind CSS + Framer Motion.

## التشغيل

```bash
npm install
npm run dev      # التطوير على 0.0.0.0
npm run build    # الإنتاج
npm start
```

## التوصيل

الموقع **لا يحسب رسوم توصيل** ولا يوجد حدّ لتوصيل مجاني: الإجمالي المعروض هو قيمة الأكل فقط،
وفي ملخص السلة ورسالة الطلب يُكتب بجانب «التوصيل» النص: **مع مندوب التوصيل** (تُعدَّل الصيغة من
`deliveryNote` في `lib/config.ts` أو من لوحة التحكم → إعدادات الموقع → الأرقام والتواصل).

## النشر على GitHub Pages (الدومين المخصص fitbite-sudan.com)

الموقع مُهيأ للتصدير الثابت (`output: 'export'`) ليعمل على Pages، ويُقدَّم من
الدومين المخصص **`https://fitbite-sudan.com`** على جذر الموقع (`/`):

- ملف الـ workflow: `.github/workflows/deploy-pages.yml` — يبني بـ `npm run build`
  **بدون أي `basePath`** عند كل push على `main` أو فرع الجلسة وينشر مجلد `out/` تلقائياً.
  ⚠️ لا تبنِ بـ `build:pages`/`NEXT_PUBLIC_BASE_PATH=/fitebite` مع الدومين المخصص:
  ستُطلب ملفات CSS/JS من `/fitebite/_next/...` فتعود 404 ويظهر الموقع كنصوص
  عارية بلا ألوان أو أشكال (هذا البناء مخصص فقط للرابط الفرعي القديم
  `fitbitesud.github.io/fitebite/`).
- ملف `public/CNAME` (وفيه `fitbite-sudan.com`) يُنسخ تلقائياً إلى `out/CNAME`
  مع كل نشر، فيبقى ربط الدومين محفوظاً ولا يضيع مع أي إعادة نشر. (يوجد أيضاً
  `CNAME` في جذر المستودع لنفس الغرض.)
- في إعدادات المستودع: **Settings → Pages → Source = GitHub Actions** (مرة واحدة)،
  و **Custom domain = `fitbite-sudan.com`**، وفعّل **Enforce HTTPS** بعد ظهوره.
- رابط الموقع بعد النشر: `https://fitbite-sudan.com/`
- للبناء محلياً بنفس إعداد الإنتاج: `npm run build` ثم افتح مجلد `out/` بأي خادم ثابت.

### شهادة الأمان (HTTPS) — تُصدَر تلقائياً من GitHub، لا تُشترى

GitHub Pages يُصدر شهادة Let's Encrypt مجاناً للدومين المخصص بشرط صحة DNS.
عند مسجّل الدومين يجب أن تكون السجلات:

| النوع | الاسم | القيمة |
| --- | --- | --- |
| `A` | `@` (الجذر) | `185.199.108.153` و`185.199.109.153` و`185.199.110.153` و`185.199.111.153` (أربعة سجلات) |
| `CNAME` | `www` | `fitbitesud.github.io` |

بعدها: **Settings → Pages** اكتب الدومين في *Custom domain* واحفظ، انتظر حتى
تظهر حالة الشهادة `approved` (قد تستغرق من دقائق حتى 24 ساعة)، ثم فعّل
**Enforce HTTPS**. إذا بقي التحذير «الشهادة غير جاهزة» فالسبب غالباً انتشار
DNS لم يكتمل أو سجل `A`/`CAA` قديم عند المسجّل — احذف أي سجلات قديمة متعارضة
وانتظر، ولا حاجة لأي تعديل في الكود. وتذكّر إضافة `https://fitbite-sudan.com`
في Sanity → API → CORS Origins حتى يعمل جلب بيانات لوحة التحكم على الدومين الجديد.

## الربط مع Sanity Studio لاحقاً

الموقع حالياً بياناته محلية (`lib/menu.ts`). عند ربط Sanity:

1. أنشئ مشروع Sanity Studio (مستضاف على sanity.io أو مجلد `studio/` مستقل).
2. `npm i next-sanity` واستبدل جسم `getMenu()` باستعلام GROQ الموثّق أعلى `lib/menu.ts`.
3. لأن الموقع تصدير ثابت على Pages: تُجلب البيانات **وقت البناء** داخل الـ workflow
   (ضع `SANITY_PROJECT_ID` و `SANITY_DATASET` وtoken قراءة في أسرار المستودع)،
   أو اجلبها في المتصفح (client-side) إذا أردت تحديثاً فورياً بدون إعادة نشر.
4. أنواع `lib/types.ts` مطابقة لمخطط Sanity — لا تعديل على أي مكوّن واجهة.

البيانات حالياً محلية في `lib/menu.ts` عبر `getMenu()`، والأنواع في `lib/types.ts` مصممة
لتطابق مخطط Sanity حرفياً (`menuItem` و `category` بنفس الحقول). للربط:

1. `npm i next-sanity`
2. استبدل جسم `getMenu()` باستعلام GROQ الموثّق أعلى `lib/menu.ts`.
3. لا يحتاج أي مكوّن واجهة لأي تعديل.

## تعليقات الزوار (Moderation)

- خانة التعليقات أسفل الصفحة الرئيسية (`components/Comments.tsx` + `lib/comments.ts`).
- عند ضبط توكن الكتابة، تُرسل التعليقات إلى Sanity بحالة `approved: false` ولا تظهر للزوار حتى الموافقة.
- عند غياب التوكن أو فشل الاتصال، يُحفظ التعليق على جهاز الزائر فقط ويظهر له رابط واتساب لإرساله للإدارة؛ لا يصل تلقائياً إلى لوحة التحكم في هذا الوضع.
- توكن الكتابة ذو البادئة `NEXT_PUBLIC_` سيكون مرئياً في ملفات الموقع؛ لا تستخدم توكن الإدارة، واستخدم توكناً محدود الصلاحية فقط.

## نشر تعديلات لوحة التحكم على الموقع

1. داخل Sanity Studio: اضغط **Publish** على أي وثيقة جديدة أو معدّلة (المسودات لا تظهر في الموقع).
2. بيانات الموقع والقائمة والباقات والعروض والتعليقات المعتمدة تُجلب من Sanity في المتصفح بعد أول رسم؛ بعد **Publish** حدّث الصفحة لرؤية التغيير دون إعادة بناء. جلب المتصفح يتصل بـ Sanity API مباشرة (متجاوزاً CDN) لتفادي تأخر الكاش، بينما تستخدم بيانات البناء CDN لتحميل أسرع. ويمكن تشغيل «Deploy to GitHub Pages» يدوياً من Actions، مع بناء يومي احتياطي الساعة 03:00 UTC.
3. معرّف Sanity العام `zes52trp` مضمّن في `lib/sanity/client.ts`، ومجموعة البيانات الافتراضية `production`؛ لا تُضف أسراراً أو ملفات env لهذا الجلب العام.
4. في الباقات الشهرية، أدخل السعر الشهري يدوياً؛ يظهر كما أُدخل ولا يُحسب تلقائياً. الباقة التي لا تحتوي على سعر يدوي صالح لا تظهر على الموقع.
5. في العروض الخاصة، يُخفي العرض تلقائياً بعد تاريخ «آخر تاريخ للعرض» (إن وُجد) أو عند إيقافه من مفتاح «مفعّل» — دون حذفه من اللوحة. إذا لم توجد عروض سارية يختفي القسم بالكامل.

## العروض الخاصة (القسم واللوحة)

- القسم: `components/offers/SpecialOffers.tsx` — يظهر في الصفحة الرئيسية بعد «عيّنة من القائمة»، وعنوانه (السطر الصغير/العنوان/الوصف) يُضبط من **إعدادات الموقع → نصوص صفحة الهبوط → عنوان قسم العروض الخاصة**، مع مفتاح **إظهار قسم العروض الخاصة** لإخفاء القسم بالكامل.
- البيانات: `lib/offers.ts` — بدون لوحة التحكم تظهر عروض محلية افتراضية (`DEFAULT_OFFERS`)؛ ومع ربط Sanity تُقرأ وثائق `offer` من قائمة **العروض الخاصة** في Sanity Studio.
- حقول العرض: العنوان (مطلوب)، الشارة المختصرة، الوصف، الصورة، السعر قبل العرض (مشطوب) وسعر العرض — كلاهما اختياري، آخر تاريخ للعرض (اختياري، عند تركه فارغاً يكون العرض دائماً)، مفتاح مفعّل، وترتيب العرض.
- عرض بلا عنوان صالح يُهمل، والعروض كلها غير مفعّلة/منتهية → قسم فارغ مقصود؛ ولا وثائق `offer` إطلاقاً أو خطأ شبكة → العروض المحلية.
- زر «اطلب العرض» يفتح واتساب برسالة جاهزة (`buildOfferMessage`) فيها تفاصيل العرض وحقلا الاسم والمنطقة ليملأهما العميل.

## شعار الشريط العلوي من لوحة التحكم

حقلان في **Sanity Studio → إعدادات الموقع (الشعار والنصوص والأرقام) → الهوية والشعار**:

| الحقل | أين تظهر صورته |
| --- | --- |
| **شعار الشريط العلوي (خلفية فاتحة)** | الشريط العلوي على الخلفية الفاتحة: صفحتا «القائمة» و«الباقات»، وأعلى الصفحة الرئيسية بعد التمرير — وهو الشعار الأساسي المستخدم في كل المواضع |
| **شعار الشريط العلوي (خلفية داكنة)** — اختياري | الشريط أعلى الصفحة الرئيسية قبل التمرير والتذييل (خلفية داكنة). اتركه فارغاً لِيُستخدم الشعار الأساسي في كل المواضع |

- الصيغ المقبولة: **PNG / SVG / WebP / JPG**؛ الأفضل PNG أو SVG بخلفية شفافة (شعار `public/logo.png` الحالي بخلفية كريمية معتمة، لذا يظهر على الخلفية الداكنة كمستطيل فاتح).
- الصيغ غير المدعومة (GIF و HEIC و AVIF…) يرفضها حقل اللوحة برسالة عربية قبل النشر.
- مسار الصورة: `logo.asset->url` أو `logoDark.asset->url` من `SETTINGS_QUERY` → `site.logo` / `site.logoDark` في `lib/site-data.ts` → `logoForTone()` → `imgUrl()` في `components/Logo.tsx` (يعمل مع مسار الأساس `/fitebite` في GitHub Pages).
- بعد **Publish** حدّث الصفحة ليظهر الشعار الجديد (المتصفح يقرأ مباشرة من Sanity API بعد أول رسم، بدون انتظار كاش CDN)، ولا يلزم إعادة النشر على GitHub Pages.
- الشعار لا يتغيّر في الشريط؟ تأكد أن الحقل غير فارغ، وأن الوثيقة **منشورة** (Publish لا مسودة)، وابحث عن وسم `[site-settings]` في وحدة تحكم المتصفح.

## قائمة فحص: لوحة التحكم تُحفظ لكن لا تظهر على الموقع

`SETTINGS_QUERY` في `lib/sanity/queries.ts` يقرأ **كل حقل** بـ `coalesce(المسار المتداخل, الحقل العلوي)`، فيتحمّل
شكلَي وثيقة `siteSettings` معاً: الشكل الحالي المتداخل (`identity` / `contact` / `home`) والشكل القديم المسطّح
(الحقول نفسها في جذر الوثيقة). والمصفوفات والمستندات الفرعية بنفس النمط:
`coalesce(home.heroImage.asset->url, heroImage.asset->url)` و `coalesce(home.strip[]{title,sub,icon}, strip[]{title,sub,icon})`
و`coalesce(home.cta{title,sub,primaryLabel,secondaryLabel}, cta{title,sub,primaryLabel,secondaryLabel})`.
الخروج دائماً بالشكل الذي يتوقعه `lib/site-data.ts` مهما كان شكل الوثيقة.

راجع هذه القائمة بالترتيب قبل فتح أي بلاغ:

- [ ] الوثيقة **منشورة** (Publish) لا مسودة — الاستعلام يقرأ الوثائق المنشورة فقط.
- [ ] الحقل مملوء بقيمة حقيقية: النص الفارغ/المسافات والرقم السالب يعود للقيمة الافتراضية في `lib/site-data.ts` (سلوك مقصود).
- [ ] صورة الهبوط مرفوعة في حقل الصورة نفسه؛ الرابط يُقرأ بـ `asset->url` (يبدأ بـ `https://cdn.sanity.io`).
- [ ] عند وجود أكثر من وثيقة `siteSettings`: الأحدث حسب `_updatedAt` يحسم كل حقل، والأقدم يكمل الحقول التي لم تُعدَّل.
- [ ] وحدة تحكم المتصفح: ابحث عن الوسم `[site-settings]` — كل رسائل `getSite` تبدأ به، وهي:
  - «no siteSettings values came back from Sanity» → لم يصل أي حقل قابل للاستخدام (وثيقة غير منشورة، أو فارغة، أو بشكل غير معروف).
  - «Sanity settings fetch failed» → فشل الجلب (شبكة/CORS) وتم الرجوع للقيم الافتراضية.
- [ ] بعد النشر: حدّث الصفحة (الجلب المباشر من Sanity API يبدأ بعد أول رسم ويتجاوز CDN)، أو شغّل «Deploy to GitHub Pages» من Actions.
