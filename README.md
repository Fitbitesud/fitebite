# فيتبايت 🌿 — موقع مطعم الطعام الصحي

موقع طلبات أونلاين لمطعم **فيتبايت** المتخصص في الطعام الصحي، مبني بهوية المطعم البصرية الرسمية
(أخضر زيتوني داكن + كريمي + شوكة نحاسية)، **بدون أي نص إنجليزي في الشعار** — الكلمة المرافقة
للعلامة عربية: «فيتبايت» مع سطر الهوية المترجم: «طعام صحي للضخامة والتنشيف».

## أبرز المميزات

- 🎬 **شاشة تحميل متحركة** مبنية على الشعار نفسه: القوس يُرسم، الدمبل يهبط «ويرفع»، الحرفان
  يُرسمان، الشوكة والورقة تقفزان، ثم الكلمة العربية وشريط تقدم، وستارة صاعدة تكشف الموقع
  (قابلة للتخطي بالنقر).
- 🛒 **سلة طلبات كاملة** (درج جانبي + حفظ في `localStorage` + عدّاد في الهيدر + توست إضافة).
- 📲 **تحويل السلة إلى رسالة واتساب مفصّلة** تُفتح على الرقم المسجّل في `lib/config.ts` وتشمل:
  رقم الطلب، التاريخ والوقت، بيانات العميل (اسم/جوال/منطقة/عنوان/ملاحظات/طريقة دفع)،
  كل صنف بكميته وسعره وسعراته، إجمالي السعرات والبروتين، المجموع الفرعي، التوصيل، والإجمالي.
- 🥗 قائمة مصنّفة (باولز، سلطات، مشويات وبوكسات، فطور، مشروبات) مع **ماكروز لكل وجبة**
  (سعرات/بروتين/كارب/دهون) وشارات وسوم و«الأكثر طلباً».
-  أقسام الهوية: «ما يميز فيتبايت» الأربعة من البوستر الرسمي، شريط وعود متحرك،
  كيف تطلب، آراء العملاء، بانر CTA، وفوتر كامل.
- 📱 متجاوب بالكامل RTL بخط Cairo، وأنيميشن كشف عند التمرير (Framer Motion).

## التقنية

Next.js 15 (App Router) + TypeScript + Tailwind CSS + Framer Motion.

## التشغيل

```bash
npm install
npm run dev      # التطوير على 0.0.0.0
npm run build    # الإنتاج
npm start
```

## النشر على GitHub Pages

الموقع مُهيأ للتصدير الثابت (`output: 'export'`) ليعمل على Pages:

- ملف الـ workflow: `.github/workflows/deploy-pages.yml` — يبني بـ `basePath=/fitebite`
  عند كل push على `main` أو فرع الجلسة وينشر مجلد `out/` تلقائياً.
- في إعدادات المستودع: **Settings → Pages → Source = GitHub Actions** (مرة واحدة).
- رابط الموقع بعد النشر: `https://fitbitesud.github.io/fitebite/`
- للبناء محلياً بنفس إعداد Pages: `npm run build:pages` ثم افتح مجلد `out/` بأي خادم ثابت.

## الربط مع Sanity Studio لاحقاً

الموقع حالياً بياناته محلية (`lib/menu.ts`). عند ربط Sanity:

1. أنشئ مشروع Sanity Studio (مستضاف على sanity.io أو مجلد `studio/` مستقل).
2. `npm i next-sanity` واستبدل جسم `getMenu()` باستعلام GROQ الموثّق أعلى `lib/menu.ts`.
3. لأن الموقع تصدير ثابت على Pages: تُجلب البيانات **وقت البناء** داخل الـ workflow
   (ضع `SANITY_PROJECT_ID` و `SANITY_DATASET` وtoken قراءة في أسرار المستودع)،
   أو اجلبها في المتصفح (client-side) إذا أردت تحديثاً فورياً بدون إعادة نشر.
4. أنواع `lib/types.ts` مطابقة لمخطط Sanity — لا تعديل على أي مكوّن واجهة.

البيانات حالياً محلية في `lib/menu.ts` عبر `getMenu()`، والأنواع في `lib/types.ts` مصممة
لتطابق مخطط Sanity حرفياً (`menuItem` و `category` بنفس الحقول). للربط:

1. `npm i next-sanity`
2. استبدل جسم `getMenu()` باستعلام GROQ الموثّق أعلى `lib/menu.ts`.
3. لا يحتاج أي مكوّن واجهة لأي تعديل.

## تعليقات الزوار (Moderation)

- خانة التعليقات أسفل الصفحة الرئيسية (`components/Comments.tsx` + `lib/comments.ts`).
- قبل ربط Sanity: التعليقات المعتمدة منشورة من بذور محلية، وتعليق الزائر الجديد يُحفظ في متصفحه بحالة «بانتظار الموافقة» ويصلك نصّه عبر واتساب للمراجعة.
- بعد ربط Sanity: أنشئ نوع `comment` بحقول `name / text / postedAt / approved`؛ التعليق الجديد يُنشأ بـ `approved: false` فيظهر عندك في Sanity Studio، وعند تفعيل الموافقة يُنشر تلقائياً في الموقع عبر `getApprovedComments()`.
